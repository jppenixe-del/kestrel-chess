# Licences, provenance, and credit

Kestrel is an independent implementation. This file records where its ideas
came from, what third-party code it contains, and under what terms — so that
anyone can check rather than guess.

The project's earlier rule was to keep other engines' names out of the
repository entirely. That was the wrong instinct and it has been reversed:
naming what you studied is what makes a project auditable. Silence about
provenance looks like something to hide, and it makes an honest independent
implementation indistinguishable from a copied one.

## What is in this repository

All code in `src/` is written for this project. No source file is a port,
a translation, or a copy of another engine's code.

## Network training

The evaluation network is trained with [bullet](https://github.com/jw1912/bullet)
(MIT), on positions generated by this engine's own self-play. Both the data and
the resulting network are ours; no third-party dataset is currently used.

If openly-licensed external data is added later — for example the LCZero
project's self-play data, which is published under the Open Database Licence
(ODbL-1.0) with contents under DBCL-1.0 — it will be listed above and credited
here. Note that a network trained on an ODbL database is a *Produced Work*: the
share-alike terms attach to redistributing the database, not to the network or
to the code that loads it. Attribution is still required, and would be given.

## Ideas we studied

Every modern engine builds on a body of published technique that belongs to
nobody in particular. The engines below were read to understand *concepts* —
what a term measures, why a curve has the shape it does, how a mechanism is
usually structured. The implementations here are this project's own, and where
a number was reasoned out rather than measured, the source comment says so and
shows the reasoning.

- **Sirius** (GPL status unclear — its repository carries no licence file;
  treated as all-rights-reserved until clarified, so nothing beyond published
  concepts has been taken from it) — king-safety accumulator and its danger
  curve, threat classification by defended/undefended, passed-pawn table
  structure, mobility area definition.
- **Berserk** — endgame scaling by strong-side pawn count, reverse-futility
  margin shape, mobility table structure.
- **Weiawaga / Mimir** (no licence file in either repository; treated as
  all-rights-reserved, so nothing beyond published concepts has been taken) —
  read for training practice: a separate win/draw/loss head alongside the
  score, gradient damping by feature frequency, and leaning the label further
  onto the game result than onto the search score.
- **Viridithas** — the case for coordinate-descent tuning against game
  results scored through quiescence, rather than gradient descent against
  search scores. No code or constants taken.

No values from any of these are used verbatim. Where an early version of this
engine did carry reference values directly — the mobility and threat tables
were imported at their original scale — that was found to be a defect, not a
shortcut: values calibrated against another engine's material scale are wrong
in ours, and measuring that cost is documented in the source comments.

## Licence classes we avoid entirely

No AGPL-licensed engine has been read or used. This is deliberate and it is the
one line that cannot be crossed by attribution alone: AGPLv3 §13 requires
offering source to anyone who interacts with the program *over a network*, and
this engine runs a bot on a public server. A single AGPL-derived file would
pull the whole thing under that obligation.

Audited 2026-08-04: no file under `src/` derives from an AGPL source, and no
AGPL engine source is present on the development machines.

## What counts as taking, beyond copying code

Three things are easy to treat as "just data" and are not:

- **Layout tables.** A bucket layout copied as values is copied work, even
  though it looks like a list of numbers.
- **Feature-to-index mappings.** Worse than a table, because a trained network
  is bound to the mapping it was trained on -- adopting someone's mapping means
  the network cannot be freed from it later without retraining from scratch.
- **Vectorised kernels.** The algorithm is free; a SIMD routine whose structure
  follows another's line by line is not independent just because the identifiers
  differ.

Where this project introduces bucketed inputs or output buckets, the layouts are
computed here from a stated rule, not transcribed.
